Moralis **Data Feeds** give you the complete, decoded onchain dataset, so a wallet's summary counts come straight
from data you own. This guide moves your `/wallets/:address/stats` integration onto Data Feeds, with **no per-call
limits**.

```
GET /wallets/:address/stats
```

Wallet stats are a small **dashboard of counts**, NFTs, collections, transactions, and transfers, each a `COUNT`
over a feed you already have. Every value is exact.

## How Data Feeds works

Data Feeds is a single service over one data lake of decoded onchain data, consume the **same data** however fits
your stack: stream it with your existing **Kafka / AMQP / SQS** clients (or **REST / Arrow Flight**), **land it
with the sink** into your own database, or **query it from your warehouse** (Snowflake, BigQuery, Spark, DuckDB,
dbt) via Iceberg. See [What are Data Feeds?](/data-feeds/concepts/what-are-data-feeds) for the full picture.

The stats are counts over a wallet's holdings and activity, so the **sink** is the smoothest path.

## What to expect

You're moving from a single pre-packaged response to the **data that produces it**, see
[Data Feeds vs. the legacy API](/data-feeds/concepts/data-feeds-vs-the-legacy-api) for the general model.

**Comes through exactly**
- **The counts** (`nfts`, `collections`, `transactions`, `nft_transfers`, `token_transfers`), each a `COUNT` over
  the relevant feed. No off-chain data and nothing to price, so every value is exact.

**Good to know**
- These counts are **cumulative** over the wallet's life, so they need full history for accurate totals (see the
  backfill note).

## Before you begin

- A running Data Feeds **sink** with the recipes behind balances, transfers, and NFTs (the guides linked below).
- Your `MORALIS_API_KEY` and the chain you're indexing.

<Note>
**Plan for full history.** The transaction and transfer counts span the wallet's entire life, so the underlying
recipes need to backfill the **full history** of the chain for accurate totals (run them `historical` / `hybrid`
from an early block). See [History & backfill](/data-feeds/concepts/history-and-backfill).
</Note>

## Build it with the sink (recommended)

Each stat is a `COUNT` over a feed covered by an earlier guide:

| Stat | Feed (guide) | Compute |
|---|---|---|
| `nfts` | `walletNfts` ([Wallet NFTs](/data-feeds/migration/wallet-nfts)) | count of NFTs held (`balance > 0`) |
| `collections` | `walletNfts` ([Wallet NFT collections](/data-feeds/migration/wallet-nft-collections)) | `count(DISTINCT token_address)` held |
| `transactions.total` | native txns ([Wallet native transactions](/data-feeds/migration/wallet-native-txns)) | count of txns where the wallet is `from` / `to` |
| `nft_transfers.total` | `nftTransfers` ([Wallet NFT transfers](/data-feeds/migration/wallet-nft-transfers)) | count where `from` / `to` = wallet |
| `token_transfers.total` | `tokenTransfers` ([Wallet ERC-20 transfers](/data-feeds/migration/wallet-erc20-transfers)) | count where `from` / `to` = wallet |

```sql
SELECT
  (SELECT count(*) FROM wallet_nfts WHERE wallet_address = $1 AND balance > 0)               AS nfts,
  (SELECT count(DISTINCT token_address) FROM wallet_nfts WHERE wallet_address = $1 AND balance > 0) AS collections,
  (SELECT count(*) FROM wallet_native_txns WHERE from_address = $1 OR to_address = $1)        AS transactions_total,  -- the native-txns view from guide 17
  (SELECT count(*) FROM nft_transfers WHERE from_address = $1 OR to_address = $1)             AS nft_transfers_total,
  (SELECT count(*) FROM token_transfers WHERE from_address = $1 OR to_address = $1)           AS token_transfers_total;
```

Materialize a per-wallet stats row, updated as events land, if you serve many wallets.

## Other ways to consume this data

- **Your existing message clients.** A **Kafka / AMQP / SQS** consumer keeps the counts current as events land.
- **REST / Arrow Flight.** Read the decoded block stream directly (`GET /api/v1/continuum/{namespace}/{topic}`),
  ETH namespace `0x1`, topic `master-4`.
- **Your warehouse / notebook.** Every feed is an Iceberg table, compute the counts from **Snowflake, BigQuery,
  Spark, DuckDB, dbt** without moving data.

See the **Data Feeds API reference** and **protocol guides** (Kafka / AMQP / SQS / Arrow Flight / Iceberg).

## Field mapping reference

| `/wallets/:address/stats` | Data Feeds | Fidelity |
|---|---|---|
| `nfts` | `count` over `walletNfts` | exact |
| `collections` | `count(distinct)` over `walletNfts` | exact |
| `transactions.total` | `count` of native txns | exact |
| `nft_transfers.total` | `count` over `nftTransfers` (wallet side) | exact |
| `token_transfers.total` | `count` over `tokenTransfers` (wallet side) | exact |

## Good to know

- **A dashboard of counts** over feeds you already have, all exact.
- **Cumulative counts need full history** for accurate totals.
- **`nfts`**: decide count of held token_ids vs sum of ERC-1155 amounts (see [collections](/data-feeds/migration/wallet-nft-collections)).
- **Materialize for scale**, keep a per-wallet stats row updated by streaming.
