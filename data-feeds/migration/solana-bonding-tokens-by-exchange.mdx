Moralis **Data Feeds** give you the complete, decoded onchain dataset, including every Solana launchpad event and
the live bonding-curve progress behind it, as a real-time stream you own. This guide moves your
`/token/:network/exchange/:exchange/bonding` integration onto Data Feeds, so you track which tokens are still
climbing the curve, and how far along, straight from that data lake, with **no per-call limits**.

```
GET /token/:network/exchange/:exchange/bonding
```

This is a direct migration and a sibling of [New tokens by exchange](/data-feeds/migration/solana-new-tokens-by-exchange):
the same [`tokenBondingStatus`](/data-feeds/recipes/token/token-bonding-status) recipe carries the launchpad events;
"bonding" is simply the set of tokens on a launchpad that **haven't graduated yet**, ranked by their
**bonding-curve progress**.

## How Data Feeds works

Data Feeds is a single service over one data lake of decoded onchain data, consume the **same data** however fits
your stack: stream it with your existing **Kafka / AMQP / SQS** clients (or **REST / Arrow Flight**), **land it
with the sink** into your own database, or **query it from your warehouse** via Iceberg. See
[What are Data Feeds?](/data-feeds/concepts/what-are-data-feeds) for the full picture. For a ranked, on-demand list the
**sink** is the smoothest path, so we'll use it here.

## What to expect

You're moving from a pre-packaged response to the **underlying data that produces it**, see
[Data Feeds vs. the legacy API](/data-feeds/concepts/data-feeds-vs-the-legacy-api). Applied to bonding tokens:

**Comes through exactly**
- **The token** (`tokenAddress`) and its **bonding-curve progress** (`bondingCurveProgress`), straight from the
  launchpad's `traded` events on the chain.
- **The launchpad** it's bonding on, and the token's **name** and **symbol**.

**Calculated for you, from real trades**
- **Prices** (`priceUsd`, `priceNative`), **liquidity**, and **fully diluted valuation** come from live DEX
  activity plus reserves and supply, compare with a small tolerance, or omit what you don't need.

**Yours to control**
- **What counts as "bonding."** You define it as tokens with curve progress below 100 that haven't migrated, on
  the launchpad you choose, ordered the way you want (highest progress first is the usual "closest to graduating").

**Add the extras you want**
- `logo` is off-chain, so it's not in the feed, bring your own token list or omit it.

**Good to know**
- **Progress fills in as a token trades.** A brand-new token reports no curve progress until its first trade
  (the launchpad emits progress on trading activity), exactly like the old endpoint, which has nothing to report
  for a token with no curve activity yet.

## Build it with the sink (recommended)

### Step 1: Turn on the recipe

| What you need | Recipe | Table it keeps up to date |
|---|---|---|
| Launchpad events + curve progress | `tokenBondingStatus` | `fact_launchpad_events` / `fact_token_bonding_status` (ClickHouse); `launchpad_events` (Postgres, MySQL) |
| Token decimals (authoritative), optional | `tokenMetadata` | `token_metadata` |

### Step 2: Bring it together in one view

"Bonding" tokens are those still on the curve (progress below 100, never migrated), ranked by progress:

```sql
CREATE VIEW bonding_tokens_by_exchange AS
SELECT
  token_address,
  exchange_address,
  argMaxIf(progress_percentage, block_number, progress_percentage IS NOT NULL) AS bonding_progress
FROM recipe_token_bonding_status.fact_token_bonding_status FINAL
GROUP BY token_address, exchange_address
HAVING maxIf(1, event_type = 'migrated') = 0   -- still bonding (not graduated)
   AND bonding_progress < 100;
-- query it per launchpad: WHERE exchange_address = :exchange ORDER BY bonding_progress DESC
```

`bondingCurveProgress` maps to `bonding_progress` (the latest curve reading per token). Join `token_metadata` for
decimals and your price recipe for prices, those are calculated, as noted in
[What to expect](#what-to-expect).

### Step 3: Query it from your app

```ts
import { createClient } from '@clickhouse/client';

const ch = createClient({ url: process.env.CLICKHOUSE_URL });
const PUMPFUN = '6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P';

async function getBondingTokens(exchange = PUMPFUN, limit = 50, beforeProgress?: number) {
  const { rows } = await ch.query({
    query: `
      SELECT token_address, bonding_progress
      FROM bonding_tokens_by_exchange
      WHERE exchange_address = {exchange:String}
        ${beforeProgress != null ? 'AND bonding_progress < {beforeProgress:Float64}' : ''}
      ORDER BY bonding_progress DESC
      LIMIT {limit:UInt32}`,
    query_params: { exchange, limit, beforeProgress },
    format: 'JSONEachRow',
  }).then((r) => r.json());
  return rows;
}
```

You're now tracking the bonding curve live, ranked exactly how you choose, from a dataset you own.

### Step 4: Add the extras you want

`logo` is off-chain, skip it, bring your own Solana token list, or layer one in alongside your Data Feeds tables.

## Other ways to consume this data

The **same feed** is available however you build, all reading the one data lake:

- **Your existing message clients.** Point **Kafka**, **AMQP / RabbitMQ**, or **Amazon SQS** at Data Feeds and
  react to curve progress as it updates, ideal for a live "almost graduating" board.
- **REST / Arrow Flight.** Read the decoded block stream directly (Solana, namespace `solana-mainnet`, topic
  `master-3`):
  ```
  GET /api/v1/continuum/{namespace}/{topic}            # records by position range
  GET /api/v1/continuum/{namespace}/{topic}/schema     # the topic's Arrow schema
  ```
  Each record carries the decoded `launchpadEvents` array the recipe projects from.
- **Your warehouse / notebook.** Every feed is an Iceberg table, query from Snowflake, BigQuery, Spark, DuckDB,
  dbt without moving data.

## Field mapping reference

| `/token/:network/exchange/:exchange/bonding` | Data Feeds | Fidelity |
|---|---|---|
| `tokenAddress` | `token_address` | exact |
| `bondingCurveProgress` | latest `progress_percentage` per token | exact |
| `name`, `symbol` | `fact_launchpad_events` / `token_metadata` | exact |
| `decimals` | `token_metadata.decimals` | exact |
| `priceUsd`, `priceNative` | your price recipe, newest per token | calculated |
| `liquidity` | pair reserves x price | calculated |
| `fullyDilutedValuation` | total supply x price | calculated |
| `logo` | add yourself | off-chain |

## Good to know

- **Bonding = not yet graduated.** A token leaves the bonding list when it emits a `migrated` (graduation) event,
  the view excludes those.
- **Progress is carried forward.** The latest curve reading per token is the current progress; it updates with
  each trade.
- **You pick the launchpad** via `exchange_address` (the old `:exchange`) or `launchpad_platform`.
- **No per-call limit**; page with a keyset on `bonding_progress`.
