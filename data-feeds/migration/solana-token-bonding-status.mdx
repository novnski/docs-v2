Moralis **Data Feeds** give you the complete, decoded onchain dataset, including the live bonding-curve state of
any Solana launchpad token, as a real-time stream you own. This guide moves your
`/token/:network/:address/bonding-status` integration onto Data Feeds, so you read a single token's curve progress
and graduation straight from that data lake, with **no per-call limits**.

```
GET /token/:network/:address/bonding-status
```

This is the most direct migration of the launchpad set: the [`tokenBondingStatus`](/data-feeds/recipes/token/token-bonding-status)
recipe was built around exactly this question, it keeps a **per-token, current-state row** (progress, graduated,
graduated-at), so a lookup is a single read on the mint.

## How Data Feeds works

Data Feeds is a single service over one data lake of decoded onchain data, consume the **same data** however fits
your stack: stream it with your existing **Kafka / AMQP / SQS** clients (or **REST / Arrow Flight**), **land it
with the sink** into your own database, or **query it from your warehouse** via Iceberg. See
[What are Data Feeds?](/data-feeds/concepts/what-are-data-feeds) for the full picture. For a per-token status lookup the
**sink** is the smoothest path, so we'll use it here.

## What to expect

You're moving from a pre-packaged response to the **underlying data that produces it**, see
[Data Feeds vs. the legacy API](/data-feeds/concepts/data-feeds-vs-the-legacy-api). Applied to a token's bonding status:

**Comes through exactly**
- **The token** (`mint`), its **bonding-curve progress** (`bondingProgress`), and **when it graduated**
  (`graduatedAt`), all from the token's launchpad events on the chain.

**Yours to control**
- **The recipe maintains the current state for you.** On Postgres and MySQL it's a single maintained row per
  token; on ClickHouse you read the latest state with a small aggregate, either way you decide the destination.

**Good to know**
- **Progress fills in as the token trades.** A token that has only just been created reports no curve progress
  until its first trade, the same as the old endpoint, which has nothing to report before there's curve activity.
- **`graduatedAt` is null until graduation**, it's set the moment the token emits its `migrated` event.

## Build it with the sink (recommended)

### Step 1: Turn on the recipe

| What you need | Recipe | Table it keeps up to date |
|---|---|---|
| Per-token bonding status | `tokenBondingStatus` | `token_bonding_status` (Postgres matview, MySQL trigger table); `fact_token_bonding_status` (ClickHouse) |

The recipe maintains one logical row per token: latest curve progress, graduated flag, and graduation time.

### Step 2: Query it from your app

On Postgres or MySQL, it's a single-row lookup on the maintained status table:

```ts
import { Pool } from 'pg';

const pool = new Pool({ connectionString: process.env.DATABASE_URL });

async function getBondingStatus(mint: string) {
  const { rows: [row] } = await pool.query(
    `SELECT token_address AS mint, bonding_progress, graduated, graduated_at
     FROM token_bonding_status
     WHERE token_address = $1`,
    [mint],
  );
  return row; // { mint, bonding_progress, graduated, graduated_at }
}
```

On ClickHouse, read the latest state with a small aggregate over the fact table:

```sql
SELECT token_address AS mint,
       argMaxIf(progress_percentage, (block_number, log_index),
                progress_percentage IS NOT NULL)  AS bonding_progress,
       maxIf(1, event_type = 'migrated') = 1       AS graduated,
       minIf(event_ts, event_type = 'migrated')    AS graduated_at
FROM recipe_token_bonding_status.fact_token_bonding_status FINAL
WHERE token_address = {mint:String}
GROUP BY token_address;
```

That's it, a token's bonding status, live, from a dataset you own.

## Other ways to consume this data

The **same feed** is available however you build, all reading the one data lake:

- **Your existing message clients.** Point **Kafka**, **AMQP / RabbitMQ**, or **Amazon SQS** at Data Feeds and
  track a token's curve as it updates.
- **REST / Arrow Flight.** Read the decoded block stream directly (Solana, namespace `solana-mainnet`, topic
  `master-3`):
  ```
  GET /api/v1/continuum/{namespace}/{topic}            # records by position range
  GET /api/v1/continuum/{namespace}/{topic}/schema     # the topic's Arrow schema
  ```
  Each record carries the decoded `launchpadEvents` array the recipe projects from.
- **Your warehouse / notebook.** Every feed is an Iceberg table, query from Snowflake, BigQuery, Spark, DuckDB,
  dbt without moving data.

## Field mapping reference

| `/token/:network/:address/bonding-status` | Data Feeds | Fidelity |
|---|---|---|
| `mint` | `token_bonding_status.token_address` | exact |
| `bondingProgress` | `bonding_progress` (latest curve reading) | exact |
| `graduatedAt` | `graduated_at` (the `migrated` event time) | exact |

## Good to know

- **Closest 1:1 of the launchpad set.** The recipe is named for this lookup; Postgres and MySQL keep a maintained
  per-token row, ClickHouse derives it with a small aggregate.
- **Progress is carried forward**, the latest non-null curve reading is the current value.
- **`graduated` / `graduatedAt`** come from the token's `migrated` event; both are empty until it graduates.
- **No per-call limit**, it's a point lookup on a table you own.
