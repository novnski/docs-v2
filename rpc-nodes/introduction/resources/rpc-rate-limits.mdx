## Overview

Moralis uses Compute Units (CUs) to track API usage. Rate limits ensure fair usage and system stability across all users.

## Rate Limits by Plan

| Plan | CUs Included | API Throughput | Node Throughput | Nodes |
|------|-------------|----------------|-----------------|-------|
| Free | 40,000 per day | 40 reqs/s | 100 CU/s | 2 |
| Starter | 2,000,000 per month | 40 reqs/s | 100 CU/s | 2 |
| Pro | 100,000,000 per month | 80 reqs/s | 100 CU/s | 20 |
| Business | 500,000,000 per month | 200 reqs/s | 300 CU/s | Unlimited |
| Enterprise | Custom | Custom | Unlimited | Unlimited |

All plans include archive request support. For current plan pricing, see [moralis.com/pricing](https://moralis.com/pricing).

## Understanding Throughput

- **CUs Included** - Total Compute Units available on your plan before overage applies. CU cost per method is listed on the [RPC Pricing](/rpc-nodes/pricing) page.
- **API Throughput** - Maximum requests per second across all your requests, evaluated over a rolling 4-second window. This limit is shared across all Moralis products. See [Rate Limits](/data-api/resources/rate-limits).
- **Node Throughput** - Maximum Compute Units per second on each individual RPC node, applied on top of your account-wide request rate.
- **Nodes** - Number of dedicated node endpoints available

## Avoiding Rate Limits

To stay within limits:

1. Monitor your CU consumption in the [Moralis Dashboard](https://admin.moralis.com/)
2. Keep your request rate below your plan's throughput
3. Implement exponential backoff for retries
4. Cache responses when possible
5. Use batch requests to reduce HTTP overhead (not CU cost)

## Rate Limit Response

When rate limited, you'll receive an HTTP 429 response:

```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32005,
    "message": "Rate limit exceeded"
  },
  "id": 1
}
```
