# Migrating from Tatum to Moralis

<Info>
**Moralis is a drop-in alternative to Tatum.** Moralis combines RPC node access, an enriched Web3 Data API, and real-time Streams behind a single API key — so you can replace Tatum's v4 Data API, Notifications/Subscriptions webhooks, and RPC Gateway, and consolidate your data, real-time, and RPC traffic in one place. This page maps the Tatum surface to Moralis endpoint-by-endpoint so the swap is mostly search-and-replace.
</Info>

Tatum and Moralis solve the same problem: get clean, decoded, enriched blockchain data into your app without running your own indexers. Tatum exposes this through its v4 Data API (REST endpoints under `/v4/data`), Notifications webhooks (Subscriptions), and a multichain RPC Gateway. Moralis exposes the same data through a REST Web3 Data API plus Streams. Field names differ, but the resource shapes line up — most teams write a thin response adapter and keep shipping.

## Endpoint details

Each section shows the Tatum call, the Moralis URL(s) that replace it by chain, and a runnable example. Tatum Data API calls are REST against `https://api.tatum.io` with an `x-api-key` header; the Moralis equivalents are plain REST with an `X-API-Key` header.

### Token balances by wallet

**Tatum**: `GET /v4/data/balances` with `tokenTypes=native,fungible`

| Chain  | Moralis Equivalent           | Moralis URL                                                             | Documentation                                           |
| ------ | ---------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------- |
| EVM    | Get Native & ERC20 Balances  | `https://deep-index.moralis.io/api/v2.2/wallets/:address/tokens`        | [Documentation](/data-api/evm/wallet/token-balances)    |
| Solana | Get Portfolio (native + SPL) | `https://solana-gateway.moralis.io/account/:network/:address/portfolio` | [Documentation](/data-api/solana/wallet/portfolio)      |

```bash
# Tatum
curl "https://api.tatum.io/v4/data/balances?chain=ethereum-mainnet&addresses=0xd8da6bf26964af9d7eed9e03e53415d37aa96045&tokenTypes=native,fungible" \
  -H "x-api-key: $TATUM_API_KEY"

# Moralis
curl "https://deep-index.moralis.io/api/v2.2/wallets/0xd8da6bf26964af9d7eed9e03e53415d37aa96045/tokens?chain=eth" \
  -H "X-API-Key: $MORALIS_API_KEY"
```

**Notes**: Moralis returns balance, decimals, USD price, USD value, and token metadata (symbol, name, logo, verified flag, spam flag) in one call — no separate metadata or exchange-rate lookup.

### Notifications / Subscriptions → Moralis Streams

**Tatum**: `POST /v4/subscription` (webhook notifications: `ADDRESS_EVENT`, token/NFT transfers, failed transactions, contract events)

| Feature                 | Moralis Equivalent    | Documentation                            |
| ----------------------- | --------------------- | ---------------------------------------- |
| Address activity events | EVM Streams           | [Documentation](/streams/evm-streams)    |
| Token / NFT transfers   | EVM Streams           | [Documentation](/streams/evm-streams)    |
| Contract / log events   | EVM Streams           | [Documentation](/streams/evm-streams)    |
| Solana account events   | Solana Streams        | [Documentation](/streams/solana-streams) |
| Subscription management | Streams API Reference | [Documentation](/streams/api-reference/streams/create-streams) |

```bash
# Tatum — create one subscription per address/event
curl -X POST "https://api.tatum.io/v4/subscription" \
  -H "x-api-key: $TATUM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "ADDRESS_EVENT",
    "attr": {
      "address": "0xd8da6bf26964af9d7eed9e03e53415d37aa96045",
      "chain": "ETH",
      "url": "https://your.app/webhooks/tatum"
    }
  }'

# Moralis Streams — create one stream, then attach many addresses to it
curl -X POST "https://api.moralis-streams.com/streams/evm" \
  -H "X-API-Key: $MORALIS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "webhookUrl": "https://your.app/webhooks/moralis",
    "description": "Wallet activity",
    "tag": "wallet-activity",
    "chainIds": ["0x1", "0x2105"],
    "includeNativeTxs": true,
    "includeContractLogs": true
  }'
```

**Notes**: Where Tatum creates one subscription per address per event type, Moralis Streams uses a stream-with-attached-addresses model — create the stream once and add or remove addresses dynamically without re-subscribing. Streams also adds ABI-decoded contract events and smart-filter expressions, covering the same ground as Tatum's contract-event notifications.

<Note>
Tatum's **transaction-execution and custody features** — wallet/key generation, KMS, transaction signing and broadcasting, smart-contract and token deployment/minting, Gas Pump, fee estimation, and virtual accounts — have no direct Moralis equivalent. Moralis is a data and streaming platform, not a custody or transaction-execution host. Keep that logic in your own backend (or its current Tatum integration) and call Moralis APIs for data and real-time events.
</Note>

## Chain coverage

Tatum supports 100+ blockchains across EVM, Solana, Bitcoin, Tron, and more through its RPC Gateway, with Data API coverage across a large subset. Moralis covers a comparable footprint across EVM, Solana, and Bitcoin — see [Supported Chains](/data-api/supported-chains). Before cutover, diff the chains you've configured in Tatum against the supported list and flag any gaps.

## Migration checklist

1. **Get an API key** — [Get your API key](/data-api/get-your-api-key).
2. **Map your call sites** — replace each `/v4/data/*` call with the REST equivalent above. Field names differ; most teams write a thin response adapter.
3. **Collapse multi-call patterns** — Tatum flows that fetched balances and then looked up token metadata or exchange rates separately usually become a single Moralis call.
4. **Move Notifications to Streams** — replace per-address subscriptions with one Stream per event class and attach addresses dynamically.
5. **Verify chain coverage** — diff your Tatum chain configuration against [Supported Chains](/data-api/supported-chains).
6. **(Optional) Move RPC traffic** — point your JSON-RPC calls at [Moralis RPC Nodes](/rpc-nodes/overview) to consolidate billing.

## Beyond Tatum: what Moralis adds

Once migrated, teams commonly adopt Moralis endpoints that Tatum's Data API doesn't cover:

- **Wallet PnL** — realized and unrealized PnL per wallet with token-level breakdown. See [Wallet PnL Summary](/data-api/evm/wallet/wallet-pnl-summary) and [Wallet PnL by Token](/data-api/evm/wallet/wallet-pnl).
- **Wallet Net Worth** — full USD net worth in one call. See [Wallet Net Worth](/data-api/evm/wallet/net-worth).
- **DeFi positions** — protocol positions with USD value and breakdown. See [Wallet DeFi Positions](/data-api/evm/defi/wallet-positions).
- **Token discovery** — [Trending Tokens](/data-api/universal/token/trending-tokens), [Top Gainers](/data-api/universal/token/top-gainers), [Top Losers](/data-api/universal/token/top-losers), and [Filtered Tokens](/data-api/universal/token/filtered-tokens).
- **Token holder analytics** — [Token Holder Stats](/data-api/evm/token/holders/token-holder-stats) and [Historical Token Holders](/data-api/evm/token/holders/historical-token-holders).
- **DEX & pair analytics** — [Get Swaps by Token Address](/data-api/evm/token/swaps/token-swaps) and [Pair Stats](/data-api/evm/token/swaps/pair-stats).
- **NFT discovery** — [Top NFT Collections by Market Cap](/data-api/evm/nft/discovery/nfts-by-market-cap) and [by Trading Volume](/data-api/evm/nft/discovery/nfts-by-volume).
